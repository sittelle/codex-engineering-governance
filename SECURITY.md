# Security Policy

## Reporting a vulnerability

Prefer GitHub private vulnerability reporting for this repository when the **Report a vulnerability** option is available.

Do not place exploit details, real credentials, private keys, tokens, or sensitive user data in a public issue. If private vulnerability reporting is unavailable, open only a minimal public issue asking the maintainer to provide a private reporting channel; do not include the sensitive details there.

## Supported versions

The latest published stable release is the supported public baseline. Older
stable releases may receive fixes at maintainer discretion; this project does
not promise a fixed support window or response-time SLA.

An actively evaluated release candidate may receive security corrections, but
does not carry the stable compatibility guarantee until it is published as a
stable release. Development branches and historical pre-release candidates are
not supported public release lines.

## Scope

Security reports may cover vulnerabilities in the framework tooling, release/package integrity, supply-chain handling, or governance behavior that could materially encourage or permit unsafe engineering actions.

The framework is not a compliance certification and does not remove the need for project-specific security review.
